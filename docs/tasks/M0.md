# M0: workspace skeleton

Read `docs/DESIGN.md` first. Implement only what this file lists.

## Deliverables

1. Cargo workspace at the repository root with the ten crates from DESIGN section 2, each with `#![forbid(unsafe_code)]`, a crate-level doc comment and a `Cargo.toml` that inherits `version`, `edition`, `rust-version`, `license` and `repository` from the workspace.
   - `version = "0.0.0"`, `edition = "2024"`, `license = "Apache-2.0"`, `repository = "https://github.com/navarch-dev/navarch"`.
   - Declare only the dependency edges the design allows. Crates not yet implemented stay nearly empty; do not add placeholder logic.
2. `navarch-cli` builds a binary named `navarch` with clap subcommands `hub`, `worker`, `relay`, `pair`, `join`. Each prints "not implemented yet" to stderr and exits with code 2. `navarch --version` and `navarch --help` work.
3. Shared plumbing in `navarch-proto`: `MachineId` and `TaskId` newtypes with `Display`, `FromStr`, serde, and tests. No other protocol types yet.
4. A `home` helper (in `navarch-cli` or a small module of `navarch-store`; pick one and say why in the PR notes) that resolves `NAVARCH_HOME` or `~/.navarch`, creating it with mode 0700.
5. Tooling: `rustfmt.toml`, workspace `[lints]` table (deny `unsafe_code`, warn `clippy::pedantic` selectively is not required; at minimum `clippy::unwrap_used` and `clippy::expect_used` denied outside tests), `.gitignore`, `NOTICE`.
6. CI: `.github/workflows/ci.yml` running fmt check, clippy with `-D warnings`, and tests on `ubuntu-latest` and `macos-latest`, stable toolchain, with cargo caching.
7. ACP crate check: `crates/navarch-acp/examples/acp_smoke.rs`, using the official `agent-client-protocol` crate as a client. Given an adapter command on the command line, it runs `initialize`, `session/new` in a temp directory, one `session/prompt` ("Reply with OK only"), prints the reply text and stop reason, then `session/list`. It must auto-cancel any permission request. This example may be rough; its purpose is to confirm the crate covers the client side. Record what you learn in `docs/notes/acp-crate.md`: the crate version, which API you used for each call, anything missing or awkward (especially `session/resume`, `session/list`, config options for mode and model, and permission requests).
   - Do not run it against a real agent yourself unless a real adapter is already installed; the reviewer will run it. It must compile.

## Acceptance

- `cargo fmt --all --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace` all pass.
- `cargo run -q -p navarch-cli -- --help` lists the five subcommands.
- `cargo tree -e normal --workspace` shows no dependency edge that violates DESIGN section 2.
- No `unsafe`, no `unwrap`/`expect` outside tests and examples.

## Out of scope

Protocol messages, policy, drivers, anything networked.
