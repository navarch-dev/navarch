# M1: standalone worker

Read `docs/DESIGN.md` (sections 4 to 7 and 13) and `docs/notes/acp-crate.md` first.

## Deliverables

1. `navarch-proto`: `Envelope`, `Body` and all message types from DESIGN section 4, with serde round-trip tests, a golden JSON test per message type, and version handling. `PROTOCOL_VERSION = 1`.
2. `navarch-policy`: policy file model, loader-free parsing from a string, the `Decision` logic from section 6, and `check_dispatch(cwd, agent)`. Tests must cover: first match wins, default, path traversal (`..`), symlink escaping an allowed root, `~` expansion, command prefix matching on word boundaries, empty policy.
3. `navarch-acp`:
   - `AgentDriver`, `PermissionHandler`, `EventSink`, the request and result types, `DriverError`.
   - `AcpDriver` over the official crate, per section 5: adapter process lifecycle, lazy restart, resume with fallback to load, mode and model applied through config options, MCP servers passed to `session/new`.
   - `FakeDriver` behind the `testing` feature.
   - `fake-acp-agent` test binary that speaks ACP over stdio from a script file (JSON): replies, tool calls, permission requests, delays, a crash instruction.
   - Integration tests of `AcpDriver` against `fake-acp-agent` for every case in section 13.
4. `navarch-worker`:
   - Config and policy loading from `NAVARCH_HOME`, with clear errors that name the file and the field.
   - Session registry with atomic writes and recovery when the file is missing or corrupt (corrupt file is moved aside, not deleted).
   - A `Worker` type that owns a set of `AgentDriver`s and exposes async methods mirroring the hub-to-worker messages, returning the worker-to-hub messages through a channel. This is what M2 will connect to a link; build it now so standalone mode and hub mode share one code path.
   - Per-session prompt queue, global concurrency limit, permission flow with a pluggable escalation handler and the 10-minute timeout (injectable clock for tests).
   - Capability probe per section 7.
5. `navarch-cli` worker subcommands:
   - `navarch worker run --agent <name> --cwd <dir> [--mode <m>] [--model <m>] <prompt>`: streams agent text to stdout, prints the session ID and stop reason to stderr, exit code 0 on `end_turn`, 1 otherwise.
   - `navarch worker send --session <id> <prompt>`: same output; works after the previous process has exited.
   - `navarch worker sessions [--json]`, `navarch worker probe [--json]`, `navarch worker doctor`.
   - `navarch worker init`: writes commented example `worker.toml` and `worker-policy.toml` if absent. Never overwrites.
   - Escalated permissions: ask on the terminal when stdin is a TTY, otherwise deny.
6. `docs/worker.md`: how to configure agents and policy, with the adapter commands for Claude Code (`npx -y @agentclientprotocol/claude-agent-acp`) and Codex (`npx -y @agentclientprotocol/codex-acp`), and what each built-in mode means.

## Acceptance

- All three cargo checks pass. No test needs network access or a real agent.
- With a real adapter configured (run by the reviewer, not CI):
  - `navarch worker run --agent claude --cwd <tmp> "Create hello.txt containing hi"` creates the file when policy allows edits within roots, and does not when the policy denies.
  - `navarch worker send --session <id> "What file did you just create?"` answers correctly from a new process.
- `navarch worker run` with a `cwd` outside `allowed_roots` fails before any adapter starts, with an error that says which rule refused it.
- Killing the adapter process mid-session and sending again resumes the session.

## Out of scope

Hub, links, relay, encryption, MCP.
